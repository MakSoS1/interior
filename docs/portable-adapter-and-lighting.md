# Interior AR 0.3 — универсальный адаптер и естественный свет

## Назначение

Импортировать собственную мебель, готовую композицию или несколько независимых композиций в Android, размещать их на реальном полу через ARCore и сохранять переносимый проект. В приложении больше нет ограничения «только остров/гарнитур/холодильник».

Каждый GLB — одна **жёсткая группа**: это может быть один стул, остров со стульями или вся кухня. Несколько GLB внутри пакета — несколько независимо размещаемых групп. Число групп ограничено 32 для защиты мобильной памяти, один GLB — 200 МиБ, пакет — 512 МиБ. Эти пределы не гарантируют достаточную GPU-память на каждом телефоне.

## Самый простой вариант: файл GLB

Экспортируйте объект из Blender как glTF Binary (.glb), с материалами и встроенными текстурами. В приложении нажмите **«Импорт GLB / пакета»**, выберите файл. Добавлять модели можно также внутрь существующего проекта кнопкой **«Добавить»**.

Размеры не нормализуются: glTF по умолчанию трактуется в метрах. Для объекта с произвольным origin адаптер вычисляет нижний задний левый угол габаритов и использует его как опорную точку пола. Поворот и масштаб учитывают этот pivot, поэтому простое вращение не должно поднимать основание над полом. Это предположение подходит для мебели с горизонтальным основанием; для подвесных объектов используйте явно заданный pivot/elevation.

Импортируются статические glTF-меши и поддерживаемые Filament PBR-материалы. FBX, OBJ, .blend и CAD-файлы сначала нужно экспортировать в GLB. Скиннинг, morph-анимация и неподдерживаемые glTF-расширения не являются обещанной частью контракта. Проверка bounds использует min/max статических POSITION-accessor, а не полную физическую реконструкцию комнаты.

## Несколько групп: переносимый .interior.zip

Адаптер `tools/interior_adapter.py` не требует сторонних Python-библиотек:

```bash
python interior_adapter.py pack Cabinet.glb IslandWithStools.glb Lamp.glb --output MyKitchen.interior.zip --name "Моя кухня"
python interior_adapter.py validate MyKitchen.interior.zip
```

Имена Cabinet.glb, IslandWithStools.glb и Lamp.glb обозначают ваши реальные входные файлы, а не обязательный каталог. Каждый файл становится отдельной группой. Для моделей в миллиметрах добавьте `--units mm`, в сантиметрах — `--units cm`. Для сохранения авторской нулевой точки вместо автоматической привязки к основанию добавьте `--authored-pivot`.

В поставке есть реально созданные `adapter_demo.interior.zip`, `Cabinet_60cm.glb`, `Two_chairs.glb` и пакет трёх кухонных групп. Пример запуска без изменения названий:

```bash
python interior_adapter.py pack Cabinet_60cm.glb Two_chairs.glb --output Furniture.interior.zip --name "Тумба и два стула"
python interior_adapter.py validate Furniture.interior.zip
```

В приложении: импорт пакета → выберите группу → **«Расставить в AR»** → отметьте A/B/C на полу. Для следующей группы повторите калибровку. Внутренние расстояния объектов одного GLB остаются неизменными. Кнопка **«Копия»** создаёт новый независимо размещаемый экземпляр без дублирования исходных GLB-данных.

**«Экспорт»** сохраняет модели, группы, unit scale, pivot, относительные поправки и параметры света. После импорта на другом телефоне физические точки нужно указать заново: пакет намеренно не содержит world-pose Anchor из старой сессии.

## Экспорт непосредственно из Blender

Установите `blender_interior_export.py` как add-on или запустите файл в Blender Text Editor. Появится **File → Export → Interior AR (.interior.zip)**.

Каждая верхнеуровневая коллекция Blender экспортируется отдельным GLB. Например, коллекция «Остров» может содержать столешницу, основание и три стула; коллекция «Гарнитур» — все пристенные модули. Вложенные предметы сохраняют взаимное расположение. Порядок: установите Units → Metric, Unit Scale=1; проверьте физические размеры; создайте верхнеуровневые коллекции; экспортируйте.

Запуск без интерфейса:

```bash
blender kitchen.blend --background --python blender_interior_export.py -- --output kitchen.interior.zip
```

## Формат interior.json

Пакет — ZIP, содержащий interior.json и встроенные GLB. Пример для двух реально поставляемых моделей (SHA-256 необязателен; CLI заполняет его автоматически):

```json
{
  "format": "interior-ar",
  "schemaVersion": 1,
  "name": "Тумба и стулья",
  "groups": [
    {"id": "cabinet", "name": "Тумба", "asset": "models/Cabinet_60cm.glb", "metresPerUnit": 1.0},
    {"id": "chairs", "name": "Пара стульев", "asset": "models/Two_chairs.glb", "metresPerUnit": 1.0,
     "transform": {"position": [0.0, 0.0, 0.0], "yawDegrees": 0.0, "scale": 1.0}}
  ],
  "lighting": {"natural": true, "exposureStops": 0.0, "lock": false}
}
```

`pivot` — необязательные XYZ в исходных единицах модели; по умолчанию берётся минимум bounds. `position` — поправка относительно точки AR в метрах. Значение Y позволяет задавать подъём подвесного предмета. Масштаб применяется один раз: `metresPerUnit × transform.scale`.

Импорт блокирует выход за каталог ZIP, абсолютные пути, внешние ресурсы, повторяющиеся ID/пути, неподдерживаемую версию, неиспользуемые файлы, повреждённый BIN и несовпадение заявленного SHA-256. Неудачный пакет не должен появиться в каталоге.

## Освещение действительно в APK

`RuntimeLightController` подключён к живому `onSessionUpdated`. В нём:

- выключена фиксированная дополнительная fill-лампа, ранее подсвечивавшая мебель независимо от реальной комнаты;
- направление/цвет/интенсивность основного света берутся из Environmental HDR и сглаживаются;
- низкочастотная коррекция яркости по Y-плоскости камеры берётся сеткой, не сохраняет изображения, исключает слишком яркие окна и почти чёрные пиксели;
- применён базовый коэффициент 0.82 и ограниченный log-space фильтр; постоянный вход не даёт экспоненциального затемнения;
- уменьшение яркости касается виртуального прямого и окружающего света, а не видеопотока;
- доступны ручная поправка −2…+1 EV, естественный режим и фиксация яркости;
- SH и отражающая cubemap остаются под управлением SceneView, без ручного освобождения чужих GPU-ресурсов.

Это перенос принципов согласования света, **не** покадровый Gaussian-filter поверх видео. Привязывать тёмные пятна фонового изображения прямо к виртуальной столешнице означало бы переносить по ней тени старой мебели при движении камеры. Поэтому в APK применяется устойчивое общее согласование яркости плюс реальная пространственная HDR-оценка.

Фиксация яркости не замораживает cubemap: отражения продолжают обновляться. Мерцание из-за новых отражений, шумного tracking/depth и аппаратной автоэкспозиции требует проверки на конкретном телефоне.

## Проверка и границы результата

GitHub Actions строит настоящий APK и отдельный instrumented test APK, устанавливает оба на Android 16 AVD, запускает тесты и собирает logcat/скриншоты. Автотесты должны подтверждать импорт, переносимые группы, отображение GLB, сохранение и защиту от плохих архивов. Это сильнее, чем просмотр списка файлов APK, но всё ещё **не** натурная проверка ARCore в комнате.

Видеодемонстрация кухни использует восстановленную офлайн-траекторию и не переносится в APK как реальный ARCore world-map. Приложение использует собственный живой трекинг. Размеры кухни по фотографии остаются оценочными. Поддержка Realme 14 Pro+ и физические свет/тени/Depth проверяются только на совместимом смартфоне.

Debug APK может иметь другую подпись, чем старые временные сборки. Не удаляйте старое приложение ради обновления без сохранения ваших данных. Для распространения с гарантированными обновлениями нужен постоянный signing key владельца; приватные ключи в репозиторий не публикуются.
